# Pi extensions

This directory is both Pi's global extension directory and a Bun package used for development.
Pi auto-loads top-level `*.ts` files and direct child `*/index.ts` entrypoints. Supporting modules and tests must therefore live below an extension directory or in a directory without an `index.ts`, such as `test/` and `test-utils/`.

## Managed integrations

`herdr-agent-state.ts` is generated by Herdr and `rtk.ts` is maintained by RTK. Do not refactor or edit either implementation locally; add compatibility tests beside them instead.

## Development

```bash
bun install --frozen-lockfile
bun run check
```

`bun run check` runs Oxlint correctness checks, strict TypeScript checking, the Bun test suite, and coverage reporting. CI runs the same command on Linux and macOS whenever this package or its TypeScript configuration changes.

## Layout

- Each first-party extension uses `<name>/index.ts` as its entrypoint.
- `mcp/` provides one deliberately narrow, lazy MCP gateway backed only by `~/.config/mcp/mcp.json`. It supports stdio and HTTP/SSE tools plus automatic loopback OAuth, with reusable credentials stored in macOS Keychain; it opens no connections during startup.
- Cohesive implementation modules and colocated tests stay inside that extension directory.
- `shared/` contains reusable implementation modules and deliberately has no `index.ts`.
- `test-utils/` contains shared typed fakes.
- `test/` contains package-level discovery and managed-integration tests.
- `package.json`, `bun.lock`, `bunfig.toml`, and `.oxlintrc.json` are development infrastructure and are not Pi entrypoints.
